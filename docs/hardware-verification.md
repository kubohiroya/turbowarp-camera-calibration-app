# 実機確認の手順（#36）

実カメラで、校正から受け渡しまでを通して確かめるための手順です。[#36](https://github.com/kubohiroya/turbowarp-camera-calibration-app/issues/36)の受け入れ基準を、次の手順IDで満たします。

| #36の受け入れ基準                                                    | 手順                     |
| -------------------------------------------------------------------- | ------------------------ |
| 1台構成と2台構成の両方で校正を完了した                               | H-11、H-21               |
| 印刷板と画面表示の両方で校正を完了し、誤差・条件・所要時間を記録した | H-11、H-21（記録シート） |
| QRコードを実機で読み、内容の一致を確かめた                           | H-31、H-32               |
| ファイルの書き出し・読み込み・適合表示を実機で確かめた               | H-41〜H-45               |
| 撮影中の条件変化と、停止・「戻る」での後始末を実機で確かめた         | H-51〜H-54               |

H-61（モーションキャプチャのcamera appで読む）とH-62（ROSのツールで読む）は任意です。

判定は、手順ごとに次のどれかを記録します。

- `PASS`：成功条件を満たした。
- `FAIL`：実行できたが、期待結果と違った。
- `BLOCKED`：前提が無く実行できなかった。
- `N/A`：その環境では対象外だった。

`FAIL`のときは、画面のスクリーンショットと、`status`・`reason`の文をそのまま残してください。

### カメラの自動機能を確かめる

校正の前に、画像の幾何を変える自動機能を止めます。USBカメラの規格（UVC）では、ズーム・オートフォーカス・ホワイトバランスなどの操作項目はどれも任意で、どれを外から操作できるかは機種によります。ピントが固定でそもそも動かないカメラもあれば、ファームウェアが自動で合わせていて止められないカメラもあります。

| 機能                                                              | 校正への影響                                                                     | すること                                                                                                                    |
| ----------------------------------------------------------------- | -------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------- |
| 自動フレーミング（AppleのCenter Stage、LogitechのRightSightなど） | 人物に合わせて画像を切り出し、拡大するので、焦点距離と主点がフレームごとに変わる | **必ず切る**。macOSではカメラの使用中にコントロールセンターの「ビデオエフェクト」から切る。LogitechはLogi Tune／G HUBで切る |
| ズーム（光学・デジタル）                                          | 焦点距離が変わる                                                                 | 校正の前に固定し、以後変えない                                                                                              |
| オートフォーカス                                                  | ピント位置で焦点距離がわずかに変わる                                             | 切れるなら切り、使う距離で手動のピントに固定する。切れなければ「切れない」と記録する                                        |
| ホワイトバランス                                                  | 変わらない                                                                       | そのままでよい                                                                                                              |
| 露出・ゲイン                                                      | 変わらない（検出には影響する）                                                   | 自動のままでよいが、暗いとシャッターが遅くなり画像がぶれる                                                                  |

設定する手段は、メーカーのアプリ（Logi Tune、Logitech G HUBなど）、UVCの操作項目を扱うアプリ、Windowsではカメラのプロパティ画面（OBSの映像キャプチャデバイスの「映像の設定」など）、Linuxでは`v4l2-ctl`（例：`v4l2-ctl --set-ctrl=focus_automatic_continuous=0`）です。UVCの設定は、抜き差しや再起動で元に戻ることが多いので、校正の直前に確かめます。

記録シートの「カメラ」の欄には、自動フレーミング・ズーム・オートフォーカスを、それぞれ「切った」「切れない」「機能が無い」のどれかで書きます。

アプリ（Camera Source）はカメラの設定を読むだけで、変えません。カメラが報告した値だけを撮影条件として記録し、適合の判定と撮影中の変化の検出に使います。報告しない項目は比べられないので、たとえばピント位置を報告しないカメラでオートフォーカスが動いても、撮影中の変化としては検出されません。

## 事前準備

### P-1 SB3を用意する

既定のビルドには校正が入っています（`captureAndSolveV1`は既定ON）。

```bash
cd /Users/hiroya/Dev/turbowarp-camera-calibration-app
git checkout main && git pull
pnpm install --frozen-lockfile
pnpm check && pnpm dev
```

`pnpm dev`が示すURLを開き、「校正用SB3をダウンロード」でSB3を保存します。`public/downloads/release.json`のサイズとSHA-256を記録シートに写します（約2.7MB）。

### P-3 SB3を開く

TurboWarpでSB3を開き、機能拡張の実行許可を確認して、緑の旗を押します。

## 1. 1台構成・印刷板で校正する

PCの内蔵カメラ（または固定したUSBカメラ）の前で、印刷した板を手で持って動かします。

| ID   | 操作                                                                                                                                                                                                               | 期待結果                                                                                                                                                                                                                                                                                                           |
| ---- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| H-11 | 「校正を始める」の、印刷した板と同じマスの数（例：`10x7`）を押す。案内・傾けガイド・音に従って、板を画面の中央・四隅・近く・遠くへ動かし、上下左右へ20〜45度傾ける。完了まで続ける。開始から完了までの時間を計る。 | 途中でカメラのプレビュー、1行の案内、傾けガイドが出て、段が上がるたびに和音が鳴る。完了するとファンファーレが鳴り、プレビューとカメラの使用表示が消える。解けた画面に、3行の案内、`profile`欄、誤差の2行（「使った N枚 x.xx px」「使っていない M枚 y.yy px」）、「戻る」、右側のQRコードが、互いに重ならずに出る。 |
| H-12 | 誤差の2行を記録シートに写す。                                                                                                                                                                                      | Mは1以上、yは1.5以下。xとyが大きく離れていない（例：yがxの2倍を超えるならメモする）。                                                                                                                                                                                                                              |

| ID   | 操作                                                                                                                                             | 期待結果                                                                           |
| ---- | ------------------------------------------------------------------------------------------------------------------------------------------------ | ---------------------------------------------------------------------------------- |
| H-20 | 表示用の端末で、配布ページの「全画面で表示」か、SB3の起動画面の「ボードを表示」の`10x7`を押す。                                                  | ボードが画面いっぱいに、縦横の比を保って表示される。上に文字やモニタが重ならない。 |

## 3. QRコードを読む

解けた画面（H-11かH-21の直後）で行います。

| ID   | 操作                                                                                                                      | 期待結果                                                                         |
| ---- | ------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------- |
| H-31 | TurboWarpのステージを通常の大きさにして、スマートフォンでQRコードを読む。読んだ文字列をPCへ送り、`qr.txt`として保存する。 | 読み取れる。先頭が`image_width:`で始まり、`turbowarp_camera_source:`の行を含む。 |
| H-32 | ステージを全画面にして、もう一度読む。                                                                                    | 読み取れる。                                                                     |

読めなかったときは、ステージの表示の大きさ、スマートフォンからの距離、PCの画面の拡大率（macOSの解像度設定、Windowsの表示スケール）を記録します。プロファイルは約880バイトで、QRコードの大きさの調整は以前の約700バイトのJSONで行ったため、読めない可能性があります。

## 5. 条件の変化と後始末

| ---- | ---------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
