# TurboWarp Camera Calibration App

[English](README.md) | **日本語**

ChArUcoボードを表示し、それを使ってカメラを校正するアプリです。作ったレンズ校正プロファイルは、QRコードやファイルで持ち出せます。

## 現在の内容

- **ページ**：表示できる板は3種類（マス 10x7 / 8x6 / 6x5、内側コーナー 9x6 / 7x5 / 5x4）。その場で全画面、別ウィンドウで2画面目へ、SVGで保存、A4で印刷。拡大縮小は縦横同倍率で、余りはレターボックスにします。印刷時の1マスの公称寸法も表示します。
- **SB3**：この端末の役割を尋ねる起動画面、ステージいっぱいの板表示、ボタンを押さない自動校正。最後にプロファイルをQRコードで表示し、書き出せるリストに入れます。
- SB3と配布ページのビルド、SHA-256とサイズの記録、CI。

板を描くのはこのアプリではなく、camera-calibration拡張（`@kubohiroya/turbowarp-camera-calibration/runtime`）です。画面や紙に出る板と、検出器が探す板が同じ数字から出るので、両者がずれることはありません。このアプリが拡張から取るものの一覧は[`src/board.ts`](src/board.ts)にあります。

ボードの白いマスに入っている小さな模様はArUcoマーカーで、それぞれが周囲のコーナーに名前を与えます。そのため板が画面からはみ出していても、写っている分だけを校正に使えます。ふつうの市松模様は、どのコーナーがどれなのかを示すものが無いため、全体が写っていないと1点も使えません。**画面端に寄った視点こそ主点と歪み係数を決めるので、これは小さな違いではありません。**

## SB3の使い方

校正の経路は`captureAndSolveV1`フラグの背後にあり、既定はOFFです（[構成と開発](#構成と開発)を参照）。ONにしたSB3では次のように動きます。

### 起動画面

TurboWarpは機能拡張の実行許可を1回だけ尋ねます。Camera Source、Camera Calibration、QR Displayを1つのbundleにまとめているので、片方だけ許可して、何も起きないプロジェクトが残ることはありません。

緑の旗で起動画面が開き、ボタンが2列並びます。数字は横×縦のマスの数で、板を手に持った人が数えられるものです。

| ボタン                                        | この端末の役割                                                                             |
| --------------------------------------------- | ------------------------------------------------------------------------------------------ |
| `10x7` / `8x6` / `6x5`                        | 板を**見せる側**。ステージいっぱいに歪みなく出し、上には何も重ねません。クリックで戻ります |
| `10x7` / `8x6` / `6x5` の下の「校正を始める」 | その板を探して**校正する側**                                                               |

1台で順に両方を担うことも、2台で役割を分けることもできます。

### 校正中

押すものはありません。緑の旗で始め、停止ボタンで止めます。シャッター、solve、結果の登録はすべて自動です。

- **案内は一行**で、板の名前を含めて次にすることを言います：板を写す、別の板のようです、少し止める、位置か傾きを変える、続ける、近づける・遠ざける・大きく傾ける・端に寄せる。
- **傾けガイド**をプレビューに重ねます。板を四角形の輪郭で描いて手前の辺を広くし、採用済みの視点が最も届いていない向きを矢印で示します。カメラ画像の上に格子を描けば検出されてしまうので、マス目は描きません。拡張が計算している間は隠します。
- **音**。板を腕の先で持っていて画面を見ていない人のためです。
  - 16段の進捗それぞれに和音を鳴らし、前に置く音で4つの関門のどれかを示します。終わるとファンファーレ。
  - 倒す向きが変わったときに合図を鳴らします。音色で軸（前後／左右）、上がりか下がりで手前か奥かを示します。
  - いまの視点がどれだけ新しい傾きを足すかに応じて、クリック音が毎秒2回から20回まで速くなります。板を横へ滑らせるだけでは速くなりません。

fitに使っていない視点での誤差が1.5 px以下になるとセッションが終わります。それまでにカメラの大きさ、ズーム、フォーカス、カメラ自体が変わった場合は、エラーで終わります。「解けた」は「このカメラに使える」を意味します。

### 解けたら

- プレビューを隠し、共有カメラを止めます。
- プロファイルをCamera Sourceへ登録します。同じruntimeのほかの機能拡張がそれを読みます。
- プロファイルのJSONを`profile`リストに入れ、ステージ右側に**QRコード**（誤り訂正L、約700バイト）で表示します。スマートフォンをかざせば次の端末へ運べます。
- ファイルに保存するには、`profile`リストの項目上で右クリックして「書き出し」を選びます。ブロックからはできません。ブロックはタイマーの上で動くので、ブラウザはそれを「人が頼んだ」とは扱わないためです。
- 成功または失敗のあとにだけ「戻る」ボタンが出ます。押すとカメラを止め、セッションを片づけ、起動画面へ戻ります。

### 保存したプロファイルを読み込む

`profile`リストを右クリックして「読み込み」でファイルを選び、`i`キーを押します。アプリはカメラを起こし、そのカメラにプロファイルが合うかをCamera Sourceに判定させます。

| 判定           | 表示                                                                           |
| -------------- | ------------------------------------------------------------------------------ |
| `compatible`   | このカメラに使えます                                                           |
| `incompatible` | 合いません（撮影条件が校正時と違います）                                       |
| `undetermined` | 確かめられません。このプロファイルは適用されません。柔らかい肯定ではありません |

読み込んだプロファイルはQRコードにしません。

### 校正するときの注意

- **内部校正に実寸は要りません。** マスの実寸は fx・fy・cx・cy と歪み係数のどれにも影響せず、効くのは外部姿勢のスケールだけです。実寸が必要になるのは `turbowarp-time-space-sync` の配置校正であって、ここではありません。
- **板は傾けてください。** 正対したままのサンプルだけでは焦点距離と距離が分離できず、解が縮退します。傾けずに横へずらすだけでは足りません。傾けガイドに従ってください。
- **提示の仕方が、対象が正則な格子かどうかを決めます。** 印刷は縦横同倍率で。ディスプレイは1:1表示に（テレビは既定でオーバースキャンを掛けます）。タブレットは平らに置き、自動回転を切り、非光沢で。**プロジェクタは推奨しません** — 台形補正・斜めからの投影・プロジェクタ自身のレンズ歪みのいずれも結果を偏らせ、しかもどれも再投影誤差には現れません。
- 固定rigへ搭載したあとは角度も距離も変えにくくなります。搭載前に校正してください。搭載後は、表示した板は動かせないので**印刷板だけが使えます**。

## モード

- **模様を表示**：このページで板を全画面表示、別ウィンドウ表示、または印刷し、校正する側のカメラに見せる。
- **撮影して校正**：SB3をダウンロードしてTurboWarpで開き、表示または印刷した板でレンズを校正する。

## 依存と責務

`captureAndSolveV1`をONにしたSB3は、次の機能拡張をexact version・integrity付きで、決まった順序で埋め込みます。

| 機能拡張                                   | version | 役割                                                               |
| ------------------------------------------ | ------- | ------------------------------------------------------------------ |
| `@kubohiroya/turbowarp-camera-source`      | 0.9.1   | カメラ取得・lease・preview・撮影条件、プロファイルの契約と適合判定 |
| `@kubohiroya/turbowarp-camera-calibration` | 0.13.0  | 板の描画と検出、自動撮影と案内、Worker上のsolve（OpenCV）          |
| `@kubohiroya/turbowarp-qr-display`         | 0.1.0   | プロファイルのQRコード表示                                         |

ページは`@kubohiroya/turbowarp-app-shell` 0.2.0と、camera-calibrationの板の描画関数を使います。拡張のアルゴリズムをアプリに重複実装しません。

プロファイルの利用側（time-space-sync-app、realtime-motion-capture-app、photogrammetry-app）は、ファイルやQRコードで受け取る設計です。まだどれも読み込みません。

## 構成と開発

Node.js >=22.18.0、pnpm 11.11.0。

```bash
corepack enable
pnpm install --frozen-lockfile
pnpm check
pnpm dev
```

- config/app.json：名前、モード、説明、実装予定。
- config/feature-flags.ts：起動時固定のフラグ。`patternDisplayV1`はON、`captureAndSolveV1`はOFF。
- scripts/project.ts：SB3の正本。
- scripts/extensions.ts：埋め込む機能拡張とそのversion。
- apps/main/source：生成した展開済みSB3ソース。
- src：共通シェルを利用する配布ページ。
- public/downloads：生成SB3とrelease.json。
- dist：配布ページとダウンロードのビルド結果。

`captureAndSolveV1`がOFFのSB3は機能拡張を埋め込まず、数KBです。緑の旗では校正がこの配布物に入っていないことを表示し、カメラ許可を求めません。校正するSB3を作るには、フラグを`true`にしてから次を実行します。

```bash
pnpm source:update
pnpm check
```

project.ts、title、フラグを変更したらpnpm source:updateで生成ソースを更新します。`pnpm check`に含まれる`source:check`は、再生成せずに変えたフラグを拒否するので、ページとSB3の説明が食い違いません。生成SB3・distはGit管理対象外です。アーカイブはsb3-toolchainで生成します。
