# TurboWarp Camera Calibration App

[English](README.md) | **日本語**

ChArUcoボードの表示と撮影を1つのアプリで行い、カメラのレンズ校正プロファイルを作ってQRコードまたはファイルで渡すアプリです。

## 現在の内容

ボードの表示、自動の撮影と校正、プロファイルの受け渡しまでを実装しています。

- **ページ**：表示できる板は3種類（マス 10x7 / 8x6 / 6x5）。その場で全画面、別ウィンドウで2画面目へ、SVGで保存、印刷。拡大縮小は縦横同倍率で、余りはレターボックスにします。印刷・保存・描画されたマス寸法の表示・引き伸ばさないこと、はどれもページならでき、固定サイズのScratchステージではできません。
- **SB3**：起動画面で、この端末に板を表示するか、手元の板で校正を始めるかを選びます。撮影・計算・camera-sourceへの登録は自動で、傾けガイドの絵と音で案内します。解けたらカメラを止め、プロファイルをQRコードで表示し、ファイルに書き出せるリストにも入れます。同時にこのブラウザの保存領域（IndexedDB）にも保存するので、同じoriginで動くカメラアプリ（realtime-motion-capture-appのcamera-appなど）はファイルを運ばずにそのまま使えます。保存領域はキャッシュで、別のPCへ渡すのはQRコードかファイルです。ファイルから読み込んだプロファイルが、このカメラに使えるかも確かめられます。ページのURLに`cameraDeviceId`・`cameraWidth`・`cameraHeight`・`cameraFrameRate`があれば（複数のUSBカメラを使うアプリが、そのうち1台のためにこのアプリを開くときの指定方法です）、ブラウザが選ぶカメラではなくそのカメラをそのサイズで使い、デバイスをプロファイルに記録します。
- **機能拡張**：camera-source・camera-calibration・qr-display を exact version で固定して埋め込み、許可は1回です。板の絵は、それを検出する camera-calibration が描きます。
- SB3と配布ページのビルド、SHA-256とサイズの記録、CI。

解くまでの間にカメラの設定が変わったセッションは、solved ではなく error で終わります。解けたプロファイルは、それを作ったカメラに必ず使えます。

ボードの白いマスに入っている小さな模様はArUcoマーカーで、それぞれが周囲のコーナーに名前を与えます。そのため板が画面からはみ出していても、写っている分だけを校正に使えます。ふつうの市松模様は、どのコーナーがどれなのかを示すものが無いため、全体が写っていないと1点も使えません。**画面端に寄った視点こそ主点と歪み係数を決めるので、これは小さな違いではありません。**

### 書き出すファイルの形式

プロファイルは、ROSの`camera_calibration_parsers`が読み書きする`camera_info` YAMLで書き出します。ROSやOpenCV系のツール、SLAMツールがそのまま読める標準の書式です。ROSに置き場の無い校正日時・撮影条件・品質は`turbowarp_camera_source`の項目に入ります。ROSの読み込み処理はこの項目を無視するので、ファイルはROSでも読めます。

- **書き出し**：profile欄の項目上で右クリック→「書き出し」。リストは1行1項目なので、ファイルはYAMLそのものになります。TurboWarpは`profile.txt`という名前で保存するので、ROSのツールで使うときは拡張子を`.yaml`に変えてください。
- **QRコード**：同じYAMLを表示します（約900バイト）。
- **読み込み**：profile欄の項目上で右クリック→「読み込み」でファイルを選び、`i`を押します。読み込みダイアログは`.txt`／`.csv`／`.tsv`しか選べないので、`.yaml`にしたファイルは`.txt`に戻してください。
- **受け取る側**：camera-sourceの`register camera profile as`で自分のカメラ名として登録します。形式の契約は[`tests/profile-contract.test.ts`](tests/profile-contract.test.ts)が、インストールしたcamera-sourceの読み書きと適合判定で確かめています。

### SB3の操作

| 操作                                 | 動作                                                                                                                                         |
| ------------------------------------ | -------------------------------------------------------------------------------------------------------------------------------------------- |
| 緑の旗                               | 最初の画面を開く。この端末に板を表示するか、カメラを校正するかを選ぶ                                                                         |
| 「ボードを表示」の 10x7 / 8x6 / 6x5  | この端末に板を出す。数字は横×縦のマスの数。画面クリックで最初の画面に戻る                                                                    |
| 「校正を始める」の 10x7 / 8x6 / 6x5  | 手元の板と同じものを押すと、カメラが起動して校正が始まる                                                                                     |
| 撮影中                               | 押すものはない。画面の絵と音の案内に従って板を傾ける。撮影・計算・camera-source への登録まで自動                                             |
| 校正できたら                         | 画面のQRコードを別の端末で読み取るか、profile欄の項目上で右クリック→「書き出し」でファイルに保存。「戻る」で最初の画面へ                     |
| 「プロファイルを使う」の「読み込む」 | 校正せずに、保存したプロファイルを使う。profile欄の上で右クリック→「読み込み」でファイルを選び、「適用する」でこのカメラに使えるかを表示する |
| `i`                                  | profile欄に「読み込み」したプロファイルを適用する（「適用する」と同じ）。校正を終えた画面でも使える                                          |
| 停止ボタン                           | 校正をやめ、カメラを返す                                                                                                                     |

板はマスの数で呼びます。校正blockに渡すのは内側コーナー数で、マスの数より縦横それぞれ1つ少ない値です（10x7 の板は内側コーナー 9x6）。

### 校正するときの注意

- **内部校正に実寸は要りません。** マスの実寸は fx・fy・cx・cy と歪み係数のどれにも影響せず、効くのは外部姿勢のスケールだけです。実寸が必要になるのは `turbowarp-time-space-sync` の配置校正であって、ここではありません。
- **板は傾けてください。** 正対したままのサンプルだけでは焦点距離と距離が分離できず、解が縮退します。傾けずに横へずらすだけでは足りず、サンプルの新規性判定もそれを捕まえません。
- **提示の仕方が、対象が正則な格子かどうかを決めます。** 印刷は縦横同倍率で。ディスプレイは1:1表示に（テレビは既定でオーバースキャンを掛けます）。タブレットは平らに置き、自動回転を切り、非光沢で。**プロジェクタは推奨しません** — 台形補正・斜めからの投影・プロジェクタ自身のレンズ歪みのいずれも結果を偏らせ、しかもどれも再投影誤差には現れません。
- 固定rigへ搭載したあとは角度も距離も変えにくくなります。搭載前に校正してください。搭載後は、表示した模様は動かせないので**印刷板だけが使えます**。

## 今後の予定

- 解けた画面（QRコード・戻る）と、ファイルの書き出し・読み込みを実機で確かめる。
- 消費側アプリ（time-space-sync-app、photogrammetry-app）で、QRコード（turbowarp-jsqr）またはファイルからプロファイルを読み込む。realtime-motion-capture-app の camera app は読み込み済み。

## モード

- **ボードを表示**：ChArUcoボードを全画面表示する。別のPCやカメラから撮影する。SB3の起動画面からも表示できる。
- **撮影して校正**：表示または印刷したボードをカメラで撮影し、レンズ校正を解く。

## 依存と責務

- camera-source：カメラ取得・lease・撮影条件と、内部校正プロファイルの契約・登録先。
- camera-calibration：ChArUcoボードの描画・検出・自動シャッター・solve。OpenCVを含む。
- qr-display：解けたプロファイルをQRコードでスプライトに表示する。
- time-space-sync-app／realtime-motion-capture-app／photogrammetry-app：プロファイルの利用側。QRコードまたはファイルで受け取る。

3つの機能拡張は package.json で exact version に固定し、integrity と API manifest とともに埋め込みます（scripts/extensions.ts）。

## 構成と開発

Node.js >=22.18.0、pnpm 11.11.0。

```bash
corepack enable
pnpm install --frozen-lockfile
pnpm check
pnpm dev
```

- config/app.json：名前、モード、説明、今後の予定。
- config/feature-flags.ts：起動時固定の機能フラグ。撮影と校正（captureAndSolveV1）は既定ON。
- scripts/project.ts：起動確認用SB3の正本。
- apps/main/source：生成した展開済みSB3ソース。
- src：共通シェルを利用する配布ページ。
- public/downloads：生成SB3とrelease.json。
- dist：配布ページとダウンロードのビルド結果。

project.tsやtitleを変更したらpnpm source:updateで生成ソースを更新します。生成SB3・distはGit管理対象外です。アーカイブはsb3-toolchainで生成します。

## 段階導入と受け入れ基準

1. 関連GitHub Issueで既存実装の抽出対象、依存、DoD、切戻しを確定する。
2. 用途固有の経路を既定OFFで追加し、既存側は委譲へ置き換える。
3. 機材による統合検証で誤差・遅延・停止と復旧を記録する。
4. 本体拡張のアルゴリズムをアプリに重複実装しない。

pnpm check は、生成したSB3ソース、プロジェクトのスクリプトと配置、配布ページのビルドを確かめます。撮影・計算・傾けの案内は実機で確認済みです。解けた画面のQRコードと戻るボタンは、headless の TurboWarp でのみ確認しています。

## ロールバックとタスク管理

SB3の校正は config/feature-flags.ts の captureAndSolveV1 の後ろにあり、既定はONです。配布ページからダウンロードするSB3で、そのまま校正できます（約2.7MB）。問題があれば captureAndSolveV1 を false にして pnpm source:update で再生成すると、機能拡張を埋め込まない数KBのSB3に戻り、ページでのボード表示はそのまま使えます。

GitHub Issues とプルリクエストを進捗の正本とします。
